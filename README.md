# 文本人性化流水线

> 把保留事实与立场的 AI 草稿，迭代为更贴近读者、场景和作者语气的自然表达。

这是一个面向中文写作的 Codex Skill。它不是一键替换同义词，而是先了解文章要给谁看、准备发到哪里、哪些事实不能动，再用“改写 - 检查 - 定向再改写”的闭环交付可用版本。

## 适合解决什么

- AI 草稿读起来模板化、连接词堆砌或句式过于整齐。
- 同一份内容要改成公众号、报告、论文或社交媒体的不同语气。
- 需要在润色时保留数据、论点、禁用词和篇幅等硬约束。

## 工作方式

1. 收集目标读者、发布场景、不可修改内容和补充信息。
2. 按场景确定文体与修改目标，生成第一版改写。
3. 从词汇、句式、逻辑、情感和上下文五个维度检查，并将具体问题反馈到下一轮。
4. 达到目标或到达轮次上限后，输出最佳版本与迭代摘要。

## 快速开始

将整个目录放入 Codex 的本地 Skills 目录后重启或刷新 Skills：

```powershell
git clone https://github.com/pakho66/ai-text-humanizer-pipeline.git "$HOME\.codex\skills\ai-text-humanizer-pipeline"
```

随后直接提出类似请求：

```text
把这篇产品介绍改得更自然，读者是开发者，事实和数据不能改。
```

Skill 会先询问必要上下文，再开始迭代；完整规则见 [SKILL.md](SKILL.md)。

## 输出内容

- 最终文本
- 适用文体与读者假设
- 迭代轮次与主要调整方向
- 未能完全满足的约束或需要人工确认的事实

## 边界

本工具用于提升表达质量，不保证任何第三方检测工具的评分，也不应用于伪造作者身份、规避学术规范或改写未经授权的内容。
